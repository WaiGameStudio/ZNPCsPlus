# 1.21.8 STATUS 阶段错误修复

## 问题描述

在 Minecraft 1.21.8 服务器上，当客户端进行服务器列表 ping（STATUS 阶段）时，PacketEvents 可能在异常处理时尝试发送 `clientbound/minecraft:disconnect` 数据包。但在 1.21.8 中，这个数据包在 STATUS 阶段的编解码器中未注册，导致以下错误：

```
io.netty.handler.codec.EncoderException: Sending unknown packet 'clientbound/minecraft:disconnect'
    at net.minecraft.network.codec.IdDispatchCodec.a(SourceFile:50)
```

## 根本原因

1. PacketEvents 2.13.0 在 STATUS 阶段遇到异常
2. Minecraft 网络管理器尝试发送 disconnect 包断开连接
3. 1.21.8 的 `IdDispatchCodec` 在 STATUS 阶段不识别 disconnect 包
4. 抛出 `EncoderException` 并级联传播

**重要**：这个错误只发生在服务器列表 ping 期间，不影响真实玩家游戏体验，但会在日志中产生大量错误输出。

## 解决方案

### 实施的修复

新增两个类来处理这个问题：

#### 1. `StatusPhaseExceptionHandler`
- Netty `ChannelDuplexHandler`，拦截 STATUS 阶段的 disconnect 编码错误
- 捕获 `EncoderException` 中包含 "disconnect" 的错误
- 静默关闭连接而不传播异常

#### 2. `StatusPhaseInjector`
- 在插件启动时注入 handler 到 Netty pipeline
- 通过反射访问 `MinecraftServer` → `ServerConnection` → `NetworkManager` 链
- 注入到现有连接和未来连接的 pipeline 首部
- 在插件卸载时清理注入的 handler

### 注入时机

在 `ZNpcsPlus.onEnable()` 中，`packetEvents.init()` 之后立即注入：

```java
packetEvents.init();

// Inject STATUS phase exception handler for 1.21.8+ compatibility
statusPhaseInjector = new StatusPhaseInjector(bootstrap);
statusPhaseInjector.inject();
shutdownTasks.add(() -> statusPhaseInjector.uninject());
```

## 技术细节

### Pipeline 顺序

```
[StatusPhaseExceptionHandler] (我们的)
    ↓
[PacketEventsDecoder]
    ↓
[PacketEventsEncoder]
    ↓
[其他 Minecraft handlers]
```

通过在 pipeline 首部注入，我们可以在异常传播到更上层之前拦截并处理。

### 为什么不升级 PacketEvents？

- 当前使用的 2.13.0 是 PacketEvents 的最新稳定版本
- 2.13.1+ 版本在 Maven 仓库中不存在
- 即使有更新版本，也可能需要时间来完全修复这个边缘情况

### 为什么选择这个方案？

1. **非侵入性**：不修改 PacketEvents 源码（已 relocate 打包）
2. **向后兼容**：对旧版本 Minecraft 无影响
3. **安全**：只静默处理明确的 STATUS 阶段 disconnect 错误
4. **可维护**：清晰的注入/卸载生命周期

## 影响范围

- **修复版本**：2.1.0+
- **影响 Minecraft 版本**：1.21.8+（也可能适用于未来版本）
- **影响场景**：服务器列表 ping（STATUS 阶段）
- **玩家体验影响**：无（纯日志清理）

## 验证

构建后的插件在 1.21.8 服务器上应：
1. 不再在日志中输出 STATUS phase disconnect 错误
2. 服务器列表正常显示
3. 玩家正常加入游戏
4. NPC 功能完全正常

## 未来改进

如果 PacketEvents 官方修复此问题，可以：
1. 升级 PacketEvents 版本
2. 移除 `StatusPhaseExceptionHandler` 和 `StatusPhaseInjector`
3. 从 `ZNpcsPlus.onEnable()` 中移除注入代码
